# Проверка ТОЧКИ 2.6.0

## Аудит исходной версии 2.5.0

Изучены все текстовые файлы репозитория, ресурсы, тесты, workflow и сборочные скрипты.
База: f021bc1e9abd05ba6d2b2772ac47b0f96f31227b.
desktop.py запускал pywebview и локальный ThreadingHTTPServer; server.py обрабатывал
XLSX через engine.py/details.py, отдавал локальные ресурсы и результаты. Пользовательские
настройки записывались DesktopAPI, справочник — NameDirectory с атомарной записью и lock.
Результаты создавались только после запроса пользователя.

Изменяемые файлы: Data/settings.json, Data/collector-names.json и .bak;
Data/WebView — профиль, Data/desktop-state.json и Ошибка.txt — диагностика,
.server.json — служебное состояние серверного режима, .collector-names.lock — lock.
Кеш localStorage дублирует настройки нативного режима. Произвольных иных актуальных
пользовательских файлов при аудите не выявлено. Новая миграция использует whitelist JSON.

Сборка 2.5.0: PyInstaller onedir/windowed, ui и ICO, отдельный Fixed Version WebView2 CAB
с закреплённой контрольной суммой; GitHub Actions автоматически публиковал Portable.
Новая сборка использует тот же стек и runtime. Установка и Portable получают разные
маркеры дистрибутива, но общий код приложения. Старый автоматически публикующий workflow
заменён на проверку и выгрузку Artifacts без публикации.

## Автоматизированные проверки ветки

Текущие результаты и журналы сохраняются workflow windows.yml в .cache/validation и
Artifacts. Статус конкретного запуска должен быть проверен перед распространением EXE.
Этот исходный отчёт не объявляет ещё не завершившиеся проверки успешными.

Набор включает:
- прежние тесты расчётов, агрегаций, цветов, справочника, выбора папки и экспорта;
- установленные и Portable-пути, подменённые перенаправленные Known Folders,
  кириллицу, относительные пути и отсутствие записи в папку EXE;
- импорт трёх JSON, неверные данные и backup, конфликты, подтверждение,
  точную копию до замены, изменение файлов после просмотра, откат сбоя и пропуск;
- фактическую тихую установку Inno на Windows runner в Program Files;
- обычную кириллическую учётную запись, запуск готового EXE с PATH без Python,
  отчёты PNG/XLSX, справочник, перезапуск, ярлык «Пуск» и закрытие без taskkill;
- блокировку исходящей сети для приложения и встроенного runtime Windows Firewall;
- переход с синтетического установленного 2.5.99 (payload 2.6.0) на 2.6.0;
- удаление, сохранность JSON и отчётов, повторную установку и повторный запуск;
- метаданные EXE, регистрацию uninstall и отдельную проверку Portable.

Импорт в пакетном smoke проверяется через общий Python-модуль и затем потребляется
готовым EXE; native выбор папки и подтверждение замены требуют ручной UI-проверки.
Windows runner содержит Python для тестового harness: очищенный PATH готового EXE
проверяет независимость запуска, но не заменяет тест на чистом образе без Python.
Тихая установка не проверяет вручную все экраны мастера.

## Непроведённые ручные проверки

- Физическая Windows 10 x64 и чистая Windows 11 без установленного Python/интернета.
- Интерактивные русские страницы Inno, выбор каталога, UAC и запуск после установки.
- Native диалоги выбора Portable, подтверждения замены и выбора папки отчётов.
- Реальные режимы Windows DPI 100%, 125%, 150%, 200% на нескольких мониторах.
- Ручная проверка значков панели задач, перемещения между мониторами и всех тем UI.

Manifest объявляет asInvoker, PerMonitorV2 и longPathAware, minimum window size уменьшен
для небольших рабочих областей, CSS поддерживает узкую ширину. Это реализованные меры,
а не утверждение об успешном ручном тестировании всех DPI.

## Границы

Бизнес-логика engine.py/details.py и расчёты не меняются. В engine.py изменён только
поиск Arial: Known Folder Fonts вместо фиксированного C:/Windows/Fonts.
Нет автозагрузки, служб, телеметрии или отправки XLSX. Локальные HTTP-запросы
используют 127.0.0.1. Фоновые службы браузера отключены, нелокальные запросы runtime
направляются на локальный неиспользуемый proxy; тест дополнительно блокирует egress.

Окончательная публикация и merge в main не входят в автоматический workflow.
