# Точки · Portable

**Prod. by Saudade_meow**

Windows-приложение для подготовки отчётов по торговым точкам: просроки, обращения,
недельные итоги, Excel и готовые изображения.

## Скачать

Откройте [последний релиз](https://github.com/wyfgvcj2br-art/tochki/releases/latest), скачайте `Tochki-Portable-…-win-x64.zip`,
распакуйте **всю папку** и запустите `Точки.exe`.

Python, браузер и установленный WebView2 не требуются: они включены в комплект.
Поддерживается Windows 10/11 x64. Сборка проверяется на Windows 11;
на Windows 10 приложение применяет рекомендуемые Microsoft права чтения для AppContainer
только к папке встроенного Runtime. Используйте локальный диск или USB с правом записи.

## Что автоматизировано

- Объединение исходных XLSX по коду ТТ и дате, в том числе дополнительных выгрузок.
- Выбор торговых точек; настройки сохраняются между запусками.
- ФИО без кодов и скобок; обращения под соответствующими датами.
- Исключение пустых ФИО и неопределённых пользователей по умолчанию.
- Общий просрок, без разделения по сервисам.
- Недельный процент: сумма просроченных / сумма успешных заказов, два знака после запятой.
- Цвета: ≤6% зелёный, ≥6% и ≤10% светло-красный, >10% красный.
- XLSX, дополнительный журнал «ТТ × дни», раскрытая иерархия и отдельные PNG по ТТ.
- Изображения без служебных букв столбцов и номеров строк.
- Проверки повторов и конфликтов; результат проверки включён в архив.

Входные файлы — исходные выгрузки, а не снимки и не уже оформленные отчёты.

## Portable-структура

```text
Tochki-Portable/
  Точки.exe
  _internal/       # Python и библиотеки
  WebView2/        # собственный Fixed Version Runtime
  Data/           # настройки, профиль окна и диагностика
  Результаты/     # созданные отчёты
  licenses/
```

Настройки и отчёты не записываются в AppData. Для переноса закройте приложение
и скопируйте папку целиком. При обновлении сохраняйте `Data` и `Результаты`.
Windows может создавать собственные системные записи запуска приложения.

## Разработка и сборка

На Windows с Python 3.12:

```powershell
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests -v
# Сначала прочтите licenses/WEBVIEW2-LICENSE.txt:
python scripts/build_portable.py --accept-runtime-license
python scripts/smoke_portable.py dist/Точки
```

Фиксированная версия WebView2 и SHA-256 CAB закреплены в скрипте сборки.
Обновляйте runtime вместе с приложением. GitHub Actions создаёт ZIP, проверяет EXE
и публикует его в Releases. В Git не попадают Runtime, сборки, Data, XLSX и отчёты.

## Конфиденциальность и сторонние компоненты

Обработка XLSX выполняется локально. В репозитории нет персональных данных,
исходных рабочих выгрузок или сформированных рабочих отчётов. Тесты синтетические.
Microsoft WebView2 включён как неизменённый сторонний компонент по отдельной лицензии.
См. `licenses/WEBVIEW2-LICENSE.txt`, `PORTABLE.txt` и уведомления в Runtime.
Код приложения и сторонние компоненты лицензируются отдельно; лицензии зависимостей
сохраняются в сборке. Репозиторий не предоставляет права на компоненты Microsoft сверх их условий.


## Детализация сборщиков

Откройте отдельный режим «Детализация сборщиков». Загрузите «Итоговая таблица по магазинам по дням» и «Итоговая таблица по сборщикам по дням» за одинаковую неделю. Режим выбирает дни, в которых отношение просроченных заказов к успешным заказам ТТ не меньше 6%. Период ограничен семью календарными днями; ровно 6% включается.

В одном PNG каждой ТТ собраны все выбранные дни и сборщики с ID, отличным от 0. По каждому показаны ФИО, успешные заказы, просроченные заказы и общий процент. ТТ без превышений не получают пустое изображение. Сборщики без ФИО (кроме ID 0) сохранены с подписью «ФИО не указано»; настройка удаления неизвестных пользователей относится только к обращениям.

Дни выбираются по проценту ТТ, а все показатели детализации, включая дневные итоги, — из выгрузки сборщиков. Расхождение сумм показывается предупреждением и выделением даты; сборка продолжается с исходными числами. В основных выгрузках используются разные поля даты — начало слота и дата сборки. Агрегированные файлы не содержат номеров заказов и листов, поэтому по ним нельзя подтвердить двойной сборочный лист или выполнять дедупликацию уникальных заказов. Части одного сборщика с одним номером объединяются по коду ТТ и дате. В архив входят PNG, Excel для проверки и Проверка.json с привязками к исходным строкам. Итог детализации относится только к дням с превышением, а не ко всей неделе.


## Справочник ФИО сборщиков (2.3.0)

При загрузке выгрузки сборщиков автоматически открывается окно неизвестных ФИО: ID, торговые точки и даты. Если имя того же ID найдено в других строках, оно показано как подсказка. Найдите ФИО в 1С, введите и нажмите «Сохранить ФИО». Можно заполнить часть и вернуться позже через «ФИО сборщиков» слева. Здесь же можно исправить сохранённую привязку.

Привязки заполняют только пустые ФИО по тому же ID и сразу применяются в предпросмотре. Для готовых изображений и Excel соберите отчёт заново. Заполненное ФИО исходной выгрузки сохраняется; при конфликте со справочником появляется предупреждение. Числа, даты и исходные файлы при привязке не меняются.

Справочник хранится в `Data/collector-names.json`, резервная копия предыдущего сохранения — `.json.bak`. Он сохраняется после перезапуска и переносится вместе с папкой приложения. При обновлении перенесите свою папку `Data` в новую версию после закрытия обеих программ. Справочник не включается в публичный архив. Повреждённый файл не перезаписывается автоматически.

ID 0 временно скрыт из окна и детализации, включая её дневные итоги и проценты. Дни превышения по-прежнему выбираются по исходным итогам ТТ. Сведения об исключённых строках и их суммах записываются в `Проверка.json`. Остальные неизвестные ФИО сохраняются в отчёте. См. [дорожную карту](ROADMAP.md).
